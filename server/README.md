# 햄스터 아레나 서버 (전파폭탄 · 햄볼 대난투 · 마네킹 복싱 · 인생 시뮬레이션)

팀별 Claude 코치 챗으로 봇 페르소나를 정하고, 관리자가 버튼을 누르면 라운드가 시작되어 모든 브라우저에 생중계됩니다.

```bash
npm install
node server.js            # http://localhost:3000 — 관리자(/admin) 비번은 admin, 이 PC에 로그인된 claude CLI 계정으로 코치 실행
MOCK=1 node server.js     # 코치 없이 UI만 확인
```

- `/` 참가자: 팀 이름+비밀번호로 입장(처음 쓰는 이름이면 자동 생성) → 코치와 대화 → 페르소나 저장 → 경기 생중계·점수판
- `/admin` 관리자: 팀·페르소나 목록, **종목 전환**(전파폭탄 → 햄볼 대난투 → 마네킹 복싱 → 인생 시뮬레이션), **라운드 시작**, 속도 1/2/4×, 점수 초기화, 팀 삭제
- 종목마다 코치 규칙·페르소나 도구·엔진이 따로 (`game.js` 전파폭탄, `sumo.js` 햄볼 대난투, `boxing.js` 마네킹 복싱, `life.js` 인생 시뮬레이션). 페르소나는 종목별로 저장되고 점수판은 공유.
- 마네킹 복싱은 1대1 **토너먼트**: 라운드 시작마다 짝지어 붙이고 승자끼리 다시(홀수면 부전승), N-1경기 끝에 우승자. 3라운드×30초, 다운 3번/10카운트 KO 아니면 판정(무승부 없음). 승리 3점 + 다운 뺏을 때마다 1점. 실력은 모두 같고 팀은 스타일·몸 재질·장갑/트렁크 색·대사만 정한다(대회 전에 컨셉 확정, 이후 그대로).
- 햄볼 대난투 성격은 코치가 짓는 **규칙(스탯) 목록** — 이름 + 조건(9종) + 행동(7종) + 가중치. 가중치 합 3 초과 시 비례 축소(상호 보완), 매 순간 조건 맞는 규칙 중 가중치 큰 것이 실행.
- 인생 시뮬레이션: 팀은 코치에게 **짧게 지시**하고, 코치가 햄스터 한 명의 **성격 문서(마크다운, 1500자)**를 대필해 바로 저장한다. 난이도 장치 세 가지: ① 인생마다 메시지 N개(관리자가 정함, 기본 6) · 한 번에 300자 ② 미션마다 **금칙어**(`미션 | 금칙어, 금칙어`) — 문서에 들어가면 저장 거부(메시지는 환불) ③ 시뮬레이터는 문서의 목표·대응 규칙을 운명이 아닌 바람으로 다루고 기질·약점을 더 따르며, 심판은 미션 조건이 기록에 모두 적혀야 달성으로 본다. 관리자가 "미션 배정 · 성격 작성 시작"(시간·메시지 수 지정)을 누르면 미션이 균등·무작위로 붙고 시간이 끝나면 챗이 잠긴다. "N번째 인생 시작"마다 모든 팀이 **같은 대본**(관리자 페이지, `12: 역대급 한파` 한 줄 = 한 해, 기본 1~80세 80줄)을 산다: 팀마다 Claude 호출 2회(인생 시뮬 + 심판)로 미리 계산하고 10분(`LIFE_SEC`) 동안 나이순으로 재생. 대본·판정은 참가자와 코치에게 비공개. 미션을 달성한 인생마다 1점, 총 6번 환생(6번 뒤엔 초기화 전까지 시작 불가). 인생이 끝나면 메시지가 다시 채워지고, 코치는 지난 인생 결과를 알고 문서를 고친다. 동시 호출 수 `SIM_PAR`(8).
- 환경변수: `PORT`(3000) `ADMIN_PW`(admin) `MODEL`(haiku) `MOCK=1`(Claude 없이 키워드로 성향 추정)
- 서버는 시작할 때 같은 폴더의 `.env`(있으면)를 읽어 환경변수를 덮어쓴다 — 운영 서버의 systemd `arena.service`가 읽는 /etc/arena.env를 sudo 없이 덮어쓰는 용도. 재시작은 `sh run.sh`(프로세스를 죽이면 systemd가 3초 뒤 새로 띄움). `LIFE_MODEL`을 주면 인생 종목(코치·시뮬·심판)만 그 모델을 쓴다(기본은 `MODEL`).
- 보안(외부에 열 때): `ACCESS_KEY`를 주면 모든 페이지·API·생중계에 입장 키가 필요하다. 참가자에게 `http://주소:3000/?key=키` 링크를 주면 쿠키(7일)가 생기고 주소에서 키가 지워진다. 키·팀 비번·관리자 비번 실패는 IP당 15분 `FAILS`(20)회 넘으면 잠기고, 요청은 IP당 분당 `REQ_MAX`(1200), 생중계 연결 IP당 20, 코치 호출 팀당 10분 30회·동시 1회, 새 팀 IP당 시간당 10·전체 `MAX_TEAMS`(60). 팀 이름은 글자·숫자·공백·`_.-`만, POST는 JSON만, 보안 헤더(CSP·X-Frame-Options 등) 기본. `ADMIN_PW`는 꼭 바꿀 것.
- 데이터는 `data.json` 한 파일. 코치 호출 사용량은 `data-usage.jsonl`에 한 줄씩, 합계와 계정 사용량 창은 관리자 페이지에 표시. 팀이 8팀을 넘으면 한 라운드에 여러 경기를 자동으로 나눠 돌립니다.
- `npm test` 로 엔진·API 자체 점검.
